# Repository Study and Cleanroom Policy

Study external repositories to learn, not to disguise copying.

## Method

1. Collect candidate repositories and inspect their licenses first.
2. Study architecture, features, tests, and UX at a pattern level.
3. Extract lessons, then design an original Zandi version for our requirements.
4. Implement from scratch unless explicit license-compliant reuse is approved.
5. Validate against Zandi requirements, not superficial similarity.
6. Record sources, decisions, attribution needs, and framework lessons.

Be ethically and scientifically honest: attribute when required; do not blindly
copy, use proprietary code, violate licenses, or present copied work as
original.

## Required artifacts

For substantial projects using the Project Intelligence Gate,
`PROJECT_INTELLIGENCE_SOP.md` defines the compact artifact set and takes
precedence over this list to avoid duplicate documentation. For a standalone
cleanroom study outside that gate, use the artifacts below as appropriate.

- `REPO_STUDY.md`
- `FEATURE_MATRIX.md`
- `ARCHITECTURE_INSIGHTS.md`
- `ORIGINAL_DESIGN.md`
- `IMPLEMENTATION_PLAN.md`
- `FRAMEWORK_LESSONS.md`

External repository access, reuse, or license interpretation beyond obvious
facts requires explicit scope and, when needed, appropriate legal review.
