# Implementation planning

Plan only after the outcome and material constraints are known. Map the affected
boundaries, then order the smallest independently verifiable steps by
dependency. Each step should name its deliverable and the evidence that proves
it; fold setup, documentation, and configuration into the step that needs them.

Keep the plan in the task report unless a project contract requires a durable
artifact. Preserve established local patterns and do not turn a plan into a
mandatory worktree, TDD, subagent, or approval workflow. Return to local
authority if implementation exposes a material assumption.
